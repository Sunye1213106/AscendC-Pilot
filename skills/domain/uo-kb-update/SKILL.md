# UO 知识库更新

## 核心循环

```text
理解变更
 ↓
定位受影响 KB 实体
 ↓
评估影响范围
 ↓
制定最小更新计划
 ↓
应用更新
 ↓
复核一致性
```

## 方法

1. 把 diff 归类为程序语义变化（控制、数据、接口、模板、注册等）。
2. 用 KB/Codemap 找受影响的定义、读写、调用与导出投影。
3. 计划只覆盖真正受影响的条目；避免无证据的全量重写。
4. 应用后检查：旧锚点是否失效、新符号是否未入库、Host/Kernel 是否仍一致。
5. 证据不足的条目标 `UNRESOLVED`，不要猜。

## 结果形态

- 更新计划：触点列表 + 理由 + 风险
- 应用结果：已更新 / 跳过 / 失败原因
- 复核：`CONSISTENT` / `NEEDS_FOLLOWUP` / `UNRESOLVED`
