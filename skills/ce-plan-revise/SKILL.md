# 改计划

读当前 `{slug}_plan.md` 与目标增量。已勾选 todo 保留。只改计划 markdown。本步不是重写一份新计划，也不是开始 apply。

增量来自用户新约束、审查发现、或 `test_harness_gap` 回写。把增量融进现有结构（实现分析 / 分步 / todo / 测试内容），不要另开平行文件。

## 输入 / 输出 / 停

读：当前 `{slug}_plan.md`、增量说明。没有当前计划 → 停，应走 plan_draft 而不是 revise。

写：同一路径的计划 markdown。不要写 CE yaml。不要改源码。不要勾选未做的 todo。

完成：计划仍可被 apply 逐条执行。已勾选项仍勾选；新增工作是新的 `- [ ]`。

## 步骤

1. **定位增量落在哪一节。** 范围变了改实现分析与「不做的事」；施工顺序变了改分步；还没做的活改 todo；测试口径变了改测试内容。
2. **保留已勾选。** `- [x]` 是已经落地的事实。不要删、不要改成未做、不要把同一项拆开重做。若已做内容与新范围冲突，新增一条「回滚/收窄 xxx」todo，而不是假装没做过。
3. **新 todo 仍然一次 apply 一个。** 不要把增量揉进一条已有未勾选项里变成巨型 todo。声明文件集要可执行。
4. **测试内容仍是散文。** 给 `/tg-plan` 读，不要编码成 yaml，不要在计划里展开全量 `P-*`。
5. **查图核对新路径。** 增量点名的符号用查图确认，不要凭命名相似加文件。本步可以查图；不要开始改那些文件。
6. **停。** 不 apply、不审查、不刷 `.uo`。

## 常驻判断

`/ce-plan` 不以 PR 为输入。审查发现若要求改码，先改计划 todo，再走 apply；不要在 revise 里直接打补丁。

验证不在 CE。LLM 禁止写 `.uo`。正式产物仍是这一份 `{slug}_plan.md`。

计划必须保持可 apply：每条未完成 todo 有明确文件集与完成样子。写完后快速扫一遍有没有把已勾选改丢。

## 看到这样

| 现象 | 判断 |
| --- | --- |
| 没有当前计划 | 走 draft，不是 revise |
| 已勾选与新范围冲突 | 新增回滚/收窄 todo，不改掉 `- [x]` |
| 想把增量塞进一条巨型未勾选项 | 拆成新的 `- [ ]` |
| 想在本步打补丁 | 禁止；改计划后 apply |
| 测试口径变了 | 只改测试内容散文 |

## 完成勾选

- [ ] `- [x]` 全部还在
- [ ] 新增工作是新的未勾选项，文件集可执行
- [ ] 计划仍可被 apply 逐条执行
- [ ] 没有改源码、没有写 yaml

## 循环

1. 读当前计划与增量，决定改哪一节。
2. 所有 `- [x]` 原样保留。冲突就加回滚 todo。
3. 新工作写成新的 `- [ ]`，不要揉进旧项。
4. 增量点名的符号查图确认。
5. 停。不 apply。

## 输出形状

同一份 `{slug}_plan.md`。已勾选保持 `- [x]`。新增工作是新的 `- [ ]`。计划仍须能被 apply 逐条执行。

## 反模式

- 把整份计划重写一遍，已勾选消失
- 在 revise 里直接改源码
- 一条 todo 变成「顺便把审查意见全做了」
- 测试内容改成 yaml / 场景表
- 以 PR diff 为输入改计划
- 把已勾选拆开重做，假装没落地
- 另开平行计划文件，旧文件不再是权威

revise 是补丁，不是第二份计划。
