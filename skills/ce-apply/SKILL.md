# 按 todo 改码

一次做一个未勾选 todo。也可按 `test_harness_gap` 说明书改测试脚本。改完立刻停。本步不查图。审查和测试由后续 slash 做。

没有 `- [ ]` 就先 `/ce-plan`，不要在本步发明范围。不要内嵌双轴审查，不要另造测试意图文件。

## 输入 / 输出 / 停

读：当前 `{slug}_plan.md` 的**这一条**未勾选 todo（以及它声明的文件集）。`test_harness_gap` 路径则读说明书，改的是测试脚本仓，不是算子仓。

写：声明文件集内的源码或测试脚本。做完将该项改成 `- [x]`。每个改动点留下 `path:line`。禁止写 CE yaml。不修改 `.uo`；CodeMap 更新由工作流自动处理。

完成：声明文件集内的这次 todo 已落地。不要开始下一条。

## 步骤

1. **只改本次 todo 覆盖到的文件。** 计划写了哪些路径就动哪些。超范围的「顺手修」退回，另开 todo。
2. **按计划落地，不重新设计。** 本步不查图、不扩大范围、不把审查意见当场改成另一套实现。发现计划做不到 → 停，回去 revise，不要硬改。
3. **测试仓缺口。** `test_harness_gap` 说明书指向补列 / 补生成器时，改测试脚本仓。不要在算子仓里编 CSV 列。
4. **勾选与证据。** 做完改 `- [x]`。回复里列出 `path:line`。编译与 CodeMap 更新不是本步手工做。
5. **立刻停。** 不审查、不跑 TG、不开始下一条 todo。

## 常驻判断

验证不在 CE。建议测试走 `/tg-plan`。TG 自己从计划「测试内容」节总结，本步不写场景 yaml。

`/ce-plan` 不以 PR 为输入；本步也不审 diff。两条场景不要混用。

禁止：

- 本步查图
- 一次做多条 todo
- 改 `.uo`
- 写 `tg_plan_intent.yaml` / `ce/review/`
- 把 format 清理、无关重构塞进本次 todo

发现 todo 声明文件集不够（实际还要改另一文件）→ 停并说明，让计划 revise，不要悄悄扩大。

## 看到这样

| 现象 | 判断 |
| --- | --- |
| 没有 `- [ ]` | 先 `/ce-plan` |
| 计划做不到 | 停，回去 revise |
| 顺手还想改别的文件 | 禁止；另开 todo |
| `test_harness_gap` | 改测试脚本仓，不改算子仓编列 |
| 想查图 / 审查 / 开下一条 | 禁止；改完立刻停 |
| 实际还要动未声明文件 | 停并说明，不要悄悄扩大 |

## 完成勾选

- [ ] 只做了一条 todo，只动了声明文件集
- [ ] 该项已 `- [x]`，回复有 `path:line`
- [ ] 本步不查图，没有改 `.uo`，没有写 CE yaml

## 循环

1. 取出第一条 `- [ ]`。没有则停去 `/ce-plan`。
2. 只改声明文件集。计划做不到就停去 revise。
3. 落地、勾选、列出 `path:line`。
4. 立刻停。不查图，不审查，不开下一条。

`test_harness_gap` 时改测试脚本仓。不要在算子仓编列。

## 输出形状

回复列出本次改动的 `path:line`，以及被勾选的那一条 todo。不要附审查、不要附测试 yaml。本步不查图。

## 反模式

- 一次做多条 todo
- 顺手改未声明文件
- 本步查图或扩大设计
- 写 `.uo` / CE yaml
- 改完继续审查或开下一条
- 在算子仓里编测试列来「绕过」harness gap
