# 弄清要测什么（查阅用）

Target 立不住，后面的 partition 全是猜。这份文档是「测什么」的四项必答与两个易错点。

## 四项必答

缺任何一项，覆盖模型就只能靠猜。

| # | 必答 | 怎么答 |
| --- | --- | --- |
| A | **可控面** | 逐列读 `init.yaml` 的 `control.status` / `confidence`，给出可做确定 classifier 的列集合 = `confirmed` + `active`。其余列只能在 `untestable` / `needs_binding` 里点名提级 |
| B | **触发门禁** | `uo_query` 出该字段的写点，从写点回溯到入口，把**到写点的路径条件**写成合取式 —— 沿途每个被跨过的 `if (...) return` 都贡献一个否定项。逐项标类别：直接列 / 派生 / 环境 / host 局部量 / 真 opaque |
| C | **构造种子** | 现有 case 表只提供 seed 与默认值。答一个数字即可 —— 0 行也是合法答案，Solve 用 confirmed 列构造新行 |
| D | **新增 vs 既有** | 本次改动引入的符号，与同一文件里原本就有的符号，分开说。判不准的标「未证实」 |

B 的每一项都要拆到类别为止。容易归错的：奇偶/对齐/下界是**派生**，核数关系是**环境**，有 `{name} =` 赋值的 host 分支门是**可 probe**。派生与环境都不是 untestable。

## B 项的三个易错点

- **漏否定。** 写点前每一个 `if (cond) return` 都意味着路径条件里有 `¬cond`。只交正向合取式，建出来的 partition 常常恰好满足某个早退，Target 永久 MISS，且没有任何校验会报错。
- **抄错分支。** 同一个入口函数里，另一条 legacy / 兼容分支的入口门对本行为的路径条件没有贡献。把它当前置约束交上去，等于帮那条早退成立。每报一个门禁项，都要能说出它是「到写点必须成立」还是「到写点必须不成立」。
- **误杀析取支。** 写点右侧含 `||` 时先问：把一支取反后 expected 是否还能被另一支打到。能 → 那是 Dimension（切臂），不是 Guard。

## 载体分工

两个载体各出一半，混成一个就会把「能观测」误判成「覆盖缺口」。

| 载体 | 出什么 | 说明 |
| --- | --- | --- |
| **Replay**（引擎能力） | `evidence` | TilingKey、TilingData 字段、blockDim、workspace。host 侧回放，不需要 NPU |
| **测试脚本仓** | `oracle` | 精度 / 性能 / 复现比对。通常看不到任何 tiling 字段 |

测试脚本仓看不到 tiling 字段，不代表该状态不可观测 —— 先问 Replay 能不能给。

提 Replay 字段时用**解码后的纯叶子名**。TilingData 在源码里是嵌套结构，解码器展平且不带 struct 名；顺手抄成 `<结构名>.<字段名>` 会让该 Target 永远 `UNKNOWN`。
