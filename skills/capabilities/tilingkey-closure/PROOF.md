# 引理源码证明写作要求

Producer（`lemma_mine`）写 `combo_evidence` / `proof` 时必须达到本文件的标准。
仅贴一个 `file:line` **不够**——那只是定位，不是证明。

权威能力：同目录 `LEMMA.md`（七步清单与生命周期）。本文件规定**怎么写**。

## 什么算一条合格的源码证明

每条证据必须同时交代：

1. **读了哪一段源码**（函数名 + `file:line`，可多处）
2. **推理链怎么走**（从前提到结论的每一步）
3. **为什么没有被后续覆盖推翻**（全部赋值点 / early return / 分流 / guard）

等级：只有写满以上三点的候选才可标 `source_lemma`；否则保持 `reviewed_hypothesis` 或更低。

## 三种必须会写的形态

### 1. 后续赋值点被 guard 排除

当结论依赖「某字段之后不会再被改成对立值」时：

- 列出该字段的**全部**赋值点
- 对每一个可能推翻结论的赋值点，说明它被什么 guard 挡住，以及该 guard 在更早的行已被强制为真/假
- 不得只读第一处定义就下结论

### 2. 析取式取一支

当条件是 `(A || B || C)` 而引理只排除其中一支与另一维度的组合时：

- 写明取了哪一支、另两支为什么不成立
- 写明两点之间相关变量有无重赋值
- 写明该取值如何存活到 `GetTilingKey`（哪条 early return / 哪条路径会覆盖）

### 3. 条件区间重叠 ⇒ 固定对

当两个维度由**重叠的前提**各自固定时：

- 分别引用两边的赋值点与返回值
- 证明两套前提在目标实例上同时成立
- 结论必须是「只能是这对值」，不是「通常是」

## 反面教材（结构，不含算子数值）

漏看函数**第一行**的分流 / early return，会把蕴含边界画错，并在全量反例检验时误杀真实可达 Key。任何形如 `A ⇒ B` 的引理，推导前先找齐 A 的所有入口。

## Hard Constraints

- MUST NOT：用「跑了很多次没出现」代替源码链。
- MUST NOT：只写行号不写推理。
- MUST NOT：跳过「全部赋值点」检查却声称路径 B 已完成。
- MUST：每条 `combo_evidence` 可被 referee 按七步清单逐项勾选。
